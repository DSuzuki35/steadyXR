# SteadyXR and OpenXR layer editor

The user chose SteadyXR as the new application name and requested an integrated editor that lists installed OpenXR layers, removes registrations and changes ordering. The existing stabilized preview and render extension remain the product's core. Release 0.7.0.

The main C++ preview opens an on-demand Windows Forms editor, launched with the Windows PowerShell included with Windows. This editor performs no GPU work and does not load third-party layer DLLs. A small bundled C# registry store is compiled by Add-Type in that editor process. It uses checked writes, durable JSON backups and verified restoration on failure. Registry transactions are unavailable on the tested Windows build; no OS atomicity is claimed. No external runtime downloads.

Show 64-bit by default (iRacing), with 32-bit selectable. Show implicit and explicit registrations, system and current-user scopes, in enumeration order, not alphabetical order. Status distinguishes enabled registration, disabled registration, explicit-only, missing/malformed manifests, missing libraries and environment gating. This is configured order/status, not proof of what an already-running game loaded. Display active runtime read-only. Details include full manifest/DLL paths and technical layer name.

Controls: Refresh; enable/disable; remove registration; move up/down within the same scope/type/architecture; register the bundled SteadyXR layer if absent; Apply changes; Discard changes; Undo last apply. Changes are staged until Apply. Removal affects registry values only, never third-party files. Ordering is the Windows loader's registry discovery order; user and system scopes cannot be freely interleaved, and explicit layers are ultimately ordered by the application/environment. Disable reorder for explicit layers and across groups, with explanation.

Applying verifies that current registry data still matches the read snapshot, writes a backup outside version folders, checks write access, writes only the requested changes, and verifies the resulting order/data. Windows can retain deleted value slots; reordering therefore uses a fresh flat sibling key when needed, preserves key security, retains the original during replacement, and refuses unexpected child keys. Failed operations attempt restoration without knowingly overwriting external edits; incomplete restoration reports the backup and retained recovery path. Unknown value types and raw bytes are preserved; malformed entries do not prevent displaying later entries. Access denial is reported with an editor-only Run as administrator action. Opening the editor or shipping the package changes no registrations and does not restart the game. Undo uses the same conflict-checked backup and write path and does not overwrite later external edits.

The legacy HorizonLock OpenXR layer identifier, DLL filename, IPC names and settings format stay compatible; user-facing titles, descriptions and packages say SteadyXR. The layer DLL should remain byte-identical to 0.6.1. Existing preview.ini and Gaming-PC/Presets survive upgrades. Keep the user's requested delivery root C:\Users\danie\OneDrive\Simracing\Utilities\Horizon Lock VR. Finished package, corresponding source, checksums and ready-to-use Gaming-PC/Stream-PC folders live there. No automatic runtime or OBS configuration changes.

The reason for the currently absent Horizon Lock registration is unknown: current state does not identify its remover. Present that honestly and expose an explicit Register SteadyXR action. Do not silently reinstall while implementing or delivering.

Evidence: Khronos loader src/loader/manifest_file.cpp enumerates HKLM before HKCU and preserves registry value enumeration order. High-integrity games ignore HKCU. Khronos loader documentation describes implicit layers before explicit environment/application layers. Fred Emmott's OpenXR layer guidance explains within-hive ordering boundaries. Registry enumeration order is verified after an attempted reorder instead of assuming success.

Sources: https://registry.khronos.org/OpenXR/specs/1.1/loader.html ; https://fredemmott.com/blog/2024/11/25/best-practices-for-openxr-api-layers.html
