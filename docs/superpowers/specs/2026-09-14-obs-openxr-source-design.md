# Direct SteadyXR OBS source

Implement the requested single-PC OBS integration as a Windows D3D11 input source named **SteadyXR OpenXR Capture**, in the existing OBS module. A source fits because it supplies its own images; the existing video filter remains available for the capture-card workflow. A hidden standalone-app bridge would keep another process and presentation path running, so the source consumes OpenXR frames itself instead.

Reuse the existing OpenXR channel, exact submitted frame poses, context/foveal composition and Renderer/FrameStabilizer. Add an offscreen renderer on the OBS adapter, without an HWND or swapchain. Its output is a GPU shared texture guarded with a keyed mutex: renderer writes at key 0 and publishes key 1; OBS copies to its private display texture at key 1 and releases key 0. Acquisitions use zero timeout. No CPU video readback or second game rendering is introduced. Adapter mismatch reports an actionable error.

Expose eye, output dimensions (default 3840x2160), frame rate (default 60), aspect, smoothing, stabilization, horizon leveling/adaptive leveling, crop on four sides, asymmetric reserves for each eye, Y offset, mirror limit/softness, and Stream Comfort. Import a chosen SteadyXR.ini/legacy preview.ini without writing it; OBS saves its own settings in the scene collection. Render-area extension remains in the existing layer settings and requires no registry edits from OBS.

The capture channel permits one active consumer. Sources reused across scenes share the same OBS source. A second independently created source or the standalone preview must not steal frames or overwrite an active consumer. Pausing/hiding/destroying releases ownership; crashes recover after heartbeat timeout. The standalone preview cooperates with this ownership rule. An older preview may still claim its legacy channel: the OBS source must yield and tell the user to close it.

Missing frames after two seconds produce the existing black waiting screen. Hidden/inactive capture stops requesting copies. Eye changes and reconnects clear old pose/image state. Respect the existing build's 30-day expiration and retain version 0.7.0 as requested. Neither source nor tests modify live OpenXR, SteamVR or OBS settings. Support the same stereo/quad-view D3D11 OpenXR path used with normal OpenXR and the user's Pimax SteamVR driver.

Validation: native D3D11 offscreen/output synchronization tests, ownership tests with isolated channel names, settings import/clamping tests, a real libobs module harness with synthetic GPU OpenXR frames, waiting/reconnect/resolution/visibility checks, and existing regression tests. Hardware driving smoothness is verified separately by the user. Deliver drop-in obs-plugins/data, updated preview, binary/source ZIPs and checksums in the existing OneDrive location, preserving previous packages and user settings.
